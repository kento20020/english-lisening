# Mimic iOS アプリ　リリースまでのロードマップ

2026年11月23日時点。アプリの土台（`app/`）、課金の仕組み、プライバシーポリシー、Codemagic の設定はできている。ここから先は、**あなたの手続き**と**実機での確認**が中心になる。

- **目安の期間:** 最短で約1か月。却下や実機での修正を含めると、1.5〜2か月を見込む。
- **分担:** 手続き・お金・実機での確認は**あなた**、プログラムとビルドの設定は**私**。
- **Android 版:** iOS 版との違いと、並べたロードマップは [`android.md`](android.md)。

## 全体の流れ

| 段階 | やること | 担当 | 目安 | つまずきやすさ |

| 3. 課金のテスト | 購入・復元・解約をテスト用の購入で確かめる | 両方 | 数日〜1週間 | ★★★ |

## 0. 準備（アカウントと契約）　担当：あなた

- [ ] Apple Developer Program に個人で登録する（年12,980円）
- [ ] App Store Connect で、有料アプリの契約に同意し、銀行口座と税務情報（W-8BEN）を登録する
- [ ] 小規模事業者プログラムに申し込む（手数料 26% → 15%）
- [ ] 配信する国を決める。最初は**日本だけ**がおすすめ
- [ ] App Store Connect で新規 App を作り、アプリ名を確保する

**つまずきやすい所**

- **「Mimic」は、App Store ですでに使われている可能性が高い。** App Store の名前は他のアプリと重ねられない。「Mimic - 英語の発音リピート」のように言葉を足すか、名前の候補から選び直す。ホーム画面に出る名前は短いままにできる。
- **本人確認に数日かかることがある。** 写真付きの身分証が必要になる場合がある。
- **販売者欄に本名が出る。** 個人で登録する以上、避けられない。
- **EU に配信すると、住所・電話番号の公開が必要になる。** EU の法律（DSA）により、課金するアプリの開発者は連絡先を公開する決まりがある。日本だけで配信すれば不要。
- **口座と税務情報が済むまで、課金のテストができない。** 段階3の前に必ず終わらせる。

## 1. 初めてのビルド（TestFlight まで）　担当：両方

- [ ] App Store Connect のアプリの「Apple ID」（数字）を教えてもらい、私が `codemagic.yaml` に書く
- [ ] App Store Connect API キーを作る（あなた）
- [ ] Codemagic にリポジトリと API キーを登録し、配布用の証明書を作る（あなた。手順は `app/README.md`）
- [ ] 1回目のビルドを走らせる。失敗したらログを見て直す（私）
- [ ] TestFlight で自分の iPhone に入れる（あなた）

**つまずきやすい所**

- **署名（証明書とプロファイル）。** Mac なしでアプリを作るときに一番つまずきやすい。Codemagic の画面で証明書を作り忘れる、API キーの権限が足りない（App Manager で駄目なら Admin を試す）、登録した名前が `codemagic.yaml` と違う、など。
- **1回目はたいてい失敗する。** Xcode の版、部品の取り込み、ビルド番号などで止まりやすい。Codemagic の画面で失敗したステップのログを貼ってもらえれば、私が直す。
- **無料枠は月500分。** 1回15〜25分なので、月に20回くらいまで。修正のたびにビルドすると、意外と早く使い切る。
- **TestFlight に届くまで待ち時間がある。** アップロード後の処理に10〜30分ほどかかる。

## 2. 実機での確認と修正（いちばん大事）　担当：両方

今のアプリは「Web の仕組みを iPhone アプリに包む」作り方なので、**音まわりは実機で初めて分かる問題が出やすい**。ここに一番時間がかかると見込んでいる。

- [ ] `app/README.md` のチェックリストを実機で順番に確かめる（あなた）
- [ ] おかしいところを、画面録画や症状の説明で送る（あなた）
- [ ] 直して、ビルドし直す（私）

**起きそうな問題と対策**

| 起きそうなこと | 理由 | 対策 |
|---|---|---|
| 録音できない、許可が毎回聞かれる | アプリの中の Web 表示でのマイクの許可の扱い | Capacitor の設定で直す。だめなら録音だけ iPhone の仕組み（ネイティブ）に置き換える |
| 録音のあと、再生の音が小さい（受話口から出る） | 録音中の音の設定のまま再生している | 音の出し先の設定を直す。録音が終わったらマイクを止める |
| 画面上のマイクを示すオレンジの点が、ずっと消えない | Speak Back の仕組みが、一度つかんだマイクを放さない | 録音が終わるたびにマイクを放す |
| 長い音声（30分以上など）を入れると落ちる | 音源をすべてつなげて、メモリ上に1本の音声を作っている | 長さの上限と警告を付ける。将来は作り方を変える |
| ミュージックアプリの曲を選べない | iPhone の仕組み上、購入した曲などは他のアプリから読めない | 「ファイル」アプリに入れる方法の案内を、アプリとサポートページに載せる |
| 画面を消すと再生が止まる | Web の表示は裏では止まる | まずは仕様とする。必要なら後で対応する |
| 裏に回して戻ると保存できない | iOS ではデータベースとの接続が切れることがある | つなぎ直す仕組みは入れてある。実機で確かめる |

**つまずきやすい所**

- **私は iPhone の画面を直接見られない。** 実機でしか起きない問題は、あなたの説明と画面録画が頼りになる。アプリの中に「動作の記録をコピーできる画面」を作っておくと、原因探しがずっと速くなる（おすすめ）。
- **録音まわりを直すと、Speak Back の仕組みに手を入れることになる。** マイクを放す、長さに上限を付ける、などは Speak Back 側で直してから取り込むのが筋。

## 3. 課金のテスト　担当：両方

- [ ] App Store Connect で月額課金の商品を作る（製品 ID `mimic.premium.monthly`、500円、日本語の表示名と説明、審査用のスクリーンショット）（あなた）
- [ ] TestFlight で試す：2つ目のプロジェクトで案内が出る、購入、無制限になる、アプリを消して入れ直して復元、解約して期限切れ（あなた）
- [ ] 問題があれば直す（私）

**つまずきやすい所**

- **価格が表示されない（商品が読み込まれない）。** いちばんよくある。原因はたいてい次のどれか。
  - 有料アプリの契約・口座・税務情報が済んでいない
  - 商品の情報（表示名・説明・価格・スクリーンショット）が足りない
  - 製品 ID の打ち間違い
  - 商品を作ってから反映されるまで、数時間かかることがある
- **テスト用の購入は動きが本番と違う。** 月額が数分で更新されたり、テスト用のアカウントへのサインインを求められたりする。
- **家族の承認待ち（ファミリー共有）など、すぐに終わらない購入がある。** 案内の文は入れてある。

## 4. 審査の準備　担当：両方

- [ ] スクリーンショット：6.9インチの iPhone 用（1320×2868 など）、3〜5枚
- [ ] 説明文・キーワード・サポート URL・プライバシーポリシー URL・著作権の表記
- [ ] App のプライバシー：「データを収集しない」
- [ ] 年齢制限の質問票に答える
- [ ] **説明文の最後に利用規約（EULA）へのリンクを入れる**
- [ ] 月額課金の商品を、このバージョンに含める
- [ ] 審査メモ：「ログインはありません。2つ目のプロジェクトを作ろうとすると、またはプロジェクト一覧の『プレミアム』から、課金画面が開きます。」

**つまずきやすい所**

- **スクリーンショットのサイズ。** Mac のシミュレーターがないと、決まったサイズで撮りにくい。画面は Web でできているので、**私がブラウザで正確なサイズの画面を作れる**。あなたの iPhone で撮った画面を加工する方法もある。
- **利用規約（EULA）のリンクを説明文に入れ忘れる。** 課金するアプリでよくある却下理由。
- **月額課金の商品を、バージョンに含め忘れる。** 初めての課金商品は、アプリと一緒に審査に出す必要がある。

## 5. 審査とリリース　担当：両方

- [ ] 審査に出す（あなた）。多くは24時間以内に結果が出る
- [ ] 却下されたら、理由を送ってもらい、直して出し直す（両方）
- [ ] 承認されたら、自分でリリースのボタンを押す（「手動でリリース」にしておくと安心）

**よくある却下理由と対策**

| 理由（ガイドライン） | 内容 | 対策 |
|---|---|---|
| 4.2 最低限の機能 | Web サイトを包んだだけに見える | オフライン録音・アプリ内課金・共有シートなど、アプリならではの機能を審査メモで説明する。必要なら iPhone らしい機能を足す |
| 2.1 完成度 | 審査する人が課金を試せない | 段階3を済ませ、商品が承認待ちの状態になっているか確かめる |
| 3.1.2 月額課金 | 価格・期間・自動更新・利用規約の説明が足りない | アプリ内には入れてある。説明文側の EULA リンクも確認する |
| 5.1.1 データの扱い | マイクを使う理由の説明があいまい | 説明文は入れてある。指摘されたら具体的に書き直す |
| 2.3 正確な説明 | スクリーンショットや説明文が実際と違う | 実際の画面だけを使う |

**つまずきやすい所**

- **1〜2回は却下される前提で予定を組む。** 個人の初めてのアプリでは珍しくない。却下の文面（英語のことが多い）を送ってもらえれば、対応を一緒に考える。
- **4.2（最低限の機能）は、言い返すより機能を足すほうが早い。** 一番の不安要素。

## 6. リリース後の運用　担当：両方

- [ ] 不具合の報告とレビューへの対応
- [ ] Speak Back に増えた機能を取り込む（`python3 mimic/tools/sync_from_speakback.py`）
- [ ] 毎年の iOS・Xcode の更新への対応。Apple は毎年春ごろ、新しい開発環境でのビルドを求める
- [ ] 年会費の自動更新（切れるとアプリが App Store から消える）
- [ ] 売上の入金を確認し、必要なら確定申告をする（会社員の副業で、年間の所得が20万円を超えるときなど。くわしくは税務署や税理士に）

**つまずきやすい所**

- **「データが消えた」という声。** プロジェクトは端末の中だけにあるので、アプリを消すと戻らない。書き出しを促す案内を出す、将来は iCloud でのバックアップを考える。
- **iOS の大きな更新で、録音や再生の動きが変わる。** 毎年秋の新しい iOS が出たら、ひと通り確かめる。

## いちばんつまずきそうな所（順位）

1. **実機での録音・再生（段階2）。** Web の仕組みを包む作り方の一番の弱点。実機でしか分からず、私が直接見られない。
2. **課金の商品が読み込まれない（段階3）。** 契約と商品の設定がそろうまで動かない。
3. **署名とビルド（段階1）。** Mac なしでアプリを作るときの関門。最初の1回を通すまでが大変で、通ればあとは楽になる。
4. **審査での却下（段階5）。** とくに 4.2（Web を包んだだけに見える）。
5. **アプリ名が使えない（段階0）。** 早めに確かめるほど、手戻りが少ない。

## 先にやっておくと楽になること（私にできる準備）

- 動作の記録をコピーできる画面（実機での原因探しが速くなる）
- 録音が終わったらマイクを放す（オレンジの点、音の小ささの対策）
- 長い音声の上限と警告（落ちる対策）
- 音声ファイルの入れ方の案内（アプリ内とサポートページ）
- 審査用のスクリーンショットを、正確なサイズで作る

このうち、録音まわりと音声の長さの上限は、Speak Back の仕組みを変えることになる。「新しい機能は Speak Back に」という決まりに沿って、Speak Back で直してから取り込むのがよい。
