# Android 版　iOS 版との違いとロードマップ

2026年11月23日時点。iOS 版と同じ作り方（Capacitor で B Pocket を包む、ログインなしで課金、個人で出す）で Android 版も作る場合の比較。iOS 版のロードマップは [`roadmap.md`](roadmap.md)。

## まとめ

- **中身はほとんど共通にできる。** 画面と仕組み（`mimic/`、`app/src/`）はそのまま使える。違うのは「ストアに出すまでの手続き」と「課金の確かめ方」と「Android ならではの画面の扱い」。
- **手続きは Android のほうが重い。** 特に次の2つ。
  - 個人アカウントは、公開前に **12人に14日間** テストしてもらう決まりがある
  - 課金するアプリは、**住所が全世界に公開される**
- **技術面は Android のほうが楽。** 中の表示が Chrome と同じ仕組みなので、これまでパソコンの Chrome で確かめてきた動きに近い。Mac も要らず、作ったアプリを直接スマホに入れて試せる。
- **市場は大きい。** 日本では、メインのスマホの OS は Android 54.1%、iPhone 45.6%（MMD研究所、2026年8月）。ただし10〜20代は iPhone が多い。

## 比較

### お金と手続き

| | iOS（App Store） | Android（Google Play） |
|---|---|---|
| 登録料 | 年12,980円（毎年） | 25ドル（約3,750円、1回だけ） |
| 課金の手数料 | 15%（小規模事業者プログラムに申し込んだ場合） | 約15%（月額課金。日本の新ルールで「10%＋決済5%」。二次情報なので要確認） |
| 公開される情報（個人） | 販売者欄に本名。EU に配信する場合だけ住所なども | **本名と住所（全世界）**。課金するアプリは、住所の公開が必須 |
| 本人確認 | 必要な場合あり | 必要（身分証）。実機の Android 端末を持っていることの確認を求められる場合もある |
| 公開前のテスト義務 | **なし**（TestFlight は任意。人数の上限は内部100人・外部10,000人で、義務ではない。2026年11月に再確認） | **12人以上が14日間続けて参加するテストが必須**（個人アカウント）。そのあと本番公開の申請と審査 |
| 審査 | 多くは24時間以内。Web を包んだだけに見えるアプリに厳しい | 数時間〜数日（初回は1週間ほどかかることも）。中身の審査は iOS より緩めだが、申告するものが多い |
| ストアに出すもの | スクリーンショット（6.9インチ）、説明文、プライバシーの申告、年齢区分 | スクリーンショット、**フィーチャーグラフィック（1024×500）**、アイコン（512×512）、**データ セーフティの申告**、コンテンツのレーティング、対象年齢、広告の有無、アプリへのアクセス方法など |
| 毎年の対応 | 新しい Xcode でのビルドが求められる | **新しい Android に合わせた設定（いまは Android 16＝API 36）が毎年求められる**。古いままだと更新を出せない |

### 作り方と動き

| | iOS | Android |
|---|---|---|
| ビルド | Mac が必要。Codemagic（クラウドの Mac）を使う | **Mac 不要**。Linux でビルドできる。GitHub Actions（公開リポジトリなら無料）や Codemagic でも作れる |
| 実機で試す | TestFlight 経由（アップロードと処理に毎回時間がかかる） | **作ったアプリのファイル（APK）を直接スマホに入れられる**。修正して試すまでが速い |
| 中の表示の仕組み | WebKit（Safari と同じ）。録音・再生で実機でしか分からない問題が出やすい | **Chromium（Chrome と同じ）**。これまでパソコンの Chrome で確かめた動きに近く、問題が出にくい |
| 録音の形式 | mp4（AAC） | webm（Opus） |
| 消音 | 消音スイッチの対策が必要（入れてある） | 消音スイッチはなく、メディアの音量で決まる |
| 戻るボタン | なし | **戻る操作（ボタン・スワイプ）の扱いが必要**。シートや課金の案内を閉じずにアプリが終わってしまうのを防ぐ |
| 画面の端 | ノッチやホームバーの余白（対応済み） | **Android 15 以降は画面の端まで表示が広がる（エッジ・トゥ・エッジ）**。上下のバーの下に、ボタンが隠れないように直す必要がある |
| 機種の多さ | 少ない | **とても多い**。画面の大きさ・性能・Android の版がばらばら。古くて遅い機種への配慮が要る |
| 音声ファイルの入れ方 | 「ファイル」アプリから。ミュージックアプリの曲は選べない | ファイルマネージャーから。端末に保存した音声は選びやすい |
| データの保存 | アプリの中。iPhone のバックアップに入るかは要確認 | アプリの中。「データを消去」で消える。自動バックアップは容量の上限（25MB）があり、音声の多いプロジェクトは入らない可能性が高い |

### 課金の仕組み

| | iOS | Android |
|---|---|---|
| ログインなしで課金 | できる（Apple ID） | **できる**（Google アカウント） |
| 使う仕組み | StoreKit 2 | Google Play Billing（同じプラグイン `@capgo/native-purchases` で対応） |
| 期限の分かり方 | 期限の日付が端末で分かる | **期限の日付は端末では分からない**。有効な購入があるかどうかだけ分かる。猶予の計算を「最後に確かめた日から」に変える |
| 購入の確定 | 自動 | **3日以内に「確認（承認）」しないと自動で返金される**。プラグインの自動確認をオンにしておく |
| 商品の作り方 | サブスクリプション＋製品 ID | サブスクリプション＋製品 ID＋**基本プラン（例：月額）**。購入するときに基本プランの ID も必要 |
| テスト | TestFlight／テスト用アカウント | **ライセンステスター**に登録した Google アカウントで、テスト用のカードで購入。月額は数分で更新される |
| 解約の案内 | 「設定」アプリ → サブスクリプション | Google Play の「定期購入」画面へのリンクを出す |
| iOS 版との共有 | できない（ストアが別） | できない。両方で同じ課金を使いたくなったら、ログインと RevenueCat などを足す |

## Android 版で私がやること（コードの変更）

- [ ] Android のプロジェクトを追加する（`npx cap add android`）
- [ ] マイクの権限を足し、録音できるようにする
- [ ] 課金を Android 向けに分ける：基本プランの ID、購入状態の見方、猶予の計算、購入の自動確認
- [ ] 戻る操作で、シートや課金の案内が閉じるようにする
- [ ] 画面の端まで広がる表示に対応する（上下のバーの余白）
- [ ] アダプティブアイコン（Android の形の変わるアイコン）と起動画面
- [ ] フィーチャーグラフィック（1024×500）とスクリーンショット
- [ ] ビルドの設定（GitHub Actions か Codemagic）と、署名の鍵の管理
- [ ] サポートページに Android 用の説明（解約の方法など）を足す

## ロードマップ（iOS 版と並べて）

**おすすめの順番：iOS 版を先に出し、Android 版はあとから。ただし Android の「12人・14日」のテストは時間がかかるので、iOS の審査を待っている間に始める。**

| 時期の目安 | iOS | Android |
|---|---|---|
| 1〜2週目 | 準備（Apple の登録・契約）、初めてのビルド | （住所を公開するかを決める） |
| 3〜4週目 | 実機での確認と修正、課金のテスト | Google Play に登録（本人確認）、Android 版を作る（私） |
| 5〜6週目 | 審査の準備、審査に出す | 社内テスト（すぐ配れる）で自分で確かめる、課金のテスト |
| 6〜8週目 | 審査の往復、リリース | **12人以上のクローズドテストを14日間** |
| 9〜10週目 | リリース後の対応 | 本番公開の申請（審査あり）、ストアの申告、審査、リリース |

Android は登録から公開まで、テスト期間だけで最低2週間、申請や審査を入れると**1か月〜1か月半**を見込む。

## Android ならではのつまずき（順位）

1. **住所の公開。** 課金するなら、Google Play に住所が全世界に表示される。避けるには、個人事業として事務所の住所を使うなどの方法を、出す前に検討する（Google の決まりに合うかは要確認）。
2. **12人のテスターを14日間集めること。** 14日間続けて参加してもらう必要があり、途中で止めると数え直しになる。友人・家族・SNS で早めに集める。本番公開の申請では、テストの内容について質問される。
3. **機種の多さ。** 自分の端末で動いても、他の機種でボタンが隠れる・遅い・音が出ない、などが起きうる。テスターに機種を聞いておくと役に立つ。
4. **画面の端まで広がる表示と、戻る操作。** iOS にはない対応で、直し忘れると「ボタンが押せない」「すぐアプリが閉じる」と言われやすい。
5. **申告するものの多さ。** データ セーフティ、コンテンツのレーティング、対象年齢など、フォームが多い。「データを集めていない」作りなので、答え自体はシンプル。
6. **署名の鍵をなくすこと。** アップロード用の鍵は、なくすと再発行の手続きが必要になる。Google Play のアプリ署名を使い、鍵は安全な場所に保管する。

## 両方に共通して、出す前に考えておきたいこと

- **このリポジトリは公開されている。** 有料アプリのソースコードが誰でも見られる状態なので、無料のまま制限を外したコピーを作られる可能性がある。リポジトリを非公開にすると、GitHub Pages（プライバシーポリシーなどのページ）の公開に有料プランが必要になる。出す前に、どうするか決めておく。

## 決まったこと・決めてほしいこと

- **住所の公開：了承済み**（2026年11月23日）。Google Play に住所が表示されてかまわない。
- **実機：あり**（2026年11月23日）。Android の端末を持っている。動作の確認、課金のテスト、Google Play の登録時の端末の確認に使う。
- **始める時期：未定。** iOS の審査を待つ間に始める（おすすめ）か、iOS のリリース後か。
